## Introduction

The weather API is open to anyone. Most useful APIs, like AI, email, payments and maps, ask **who's calling** before they answer, so they can limit you or bill you. You prove who you are with an **API key**: a long string of letters and numbers the company gives you.

## Lesson overview

This section contains a general overview of topics that you will learn in this lesson.

- What an API key is.
- The one rule about where keys live.
- Why "real" apps have a backend.
- What to do if a key leaks.

## A hotel key card

Step through the picture:

<KeyCard />

**An API key is like a hotel key card.** It opens the door for whoever holds it, and the hotel charges the room it belongs to. The API doesn't know *who* is holding your key. It only knows *whose* key it is.

You get a key from the company's dashboard, in a section usually called **API keys**: click **Create key**, and copy it somewhere safe. Many companies show it only once.

## The one rule: keys never go in the page

Anything inside a web page reaches every visitor's browser, and anyone can read it with "View page source". So a key must live on a **server**, in its private settings, or in a special secrets file that is never published or shared (Course 4 shows you how). Never in a page, a chat message, a screenshot, a document or anywhere on GitHub.

That's why real apps have a **backend**: a part that runs on a server, out of sight. The page asks your server, your server adds the key, and only the answer travels back.

## If a key leaks

Don't panic. Act fast:

1. **Revoke it** in the company's dashboard. The old key stops working right away.
2. **Create a new one**, and put it in the safe place.
3. **Check your bill and usage** for anything you didn't do.
4. **Set a spending limit**, if the company offers one. Do this for every key, before anything goes wrong.

Bots scan public pages and code for keys all the time. A leaked AI key can turn into a big bill in a few hours.
